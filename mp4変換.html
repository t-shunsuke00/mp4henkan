🎯 このアプリについて

アプリ名：.mp4変換

用途：高校の教職員がMOV動画をMP4に変換するためのツール

対応環境：iPadのSafari、WindowsのEdge、その他のモダンブラウザ

実機での動作確認が必要です。特にiPadの古いモデルやブラウザのバージョンによっては、一部機能が利用できない場合があります。

採用構成と対応条件

変換エンジン：FFmpeg.wasm（WebAssemblyポート）

バージョン：FFmpeg 6.0系にベースした最新ビルド

ライセンス：FFmpeg本体はLGPLv2.1以上。FFmpeg.wasmはMITライセンス

iPadのSafari対応：iOS 14.5以上で、WebAssemblyとWeb Workersに対応しているバージョン。ただし、iPadのメモリが限られているため、大容量動画（1GB以上）の変換は失敗する可能性が高いです。

H.264・AACエンコード：FFmpeg.wasmは標準でH.264（H.264 / AVC）とAAC（Advanced Audio Codec）に対応しています。

WebAssemblyのメモリ消費：FFmpeg.wasmは起動時に数十～数百MBのメモリを使用します。変換対象の動画ファイルもメモリに読み込まれるため、端末のメモリが不足するとブラウザがクラッシュする可能性があります。

Web Workerの使用方法：このアプリはメインスレッドをブロックしないため、Web Workerを使用した別プロセスで変換を実行します。ただし、最新のFFmpeg.wasmビルドは単一スレッド版を使用しており、SharedArrayBufferは使用していません。

採用構成：シングルスレッド版（単一スレッド版）を採用しました。理由：iPad や古いブラウザとの互換性を重視し、クロスオリジン分離やHTTPヘッダーの設定を最小限にするためです。

セットアップ手順（Cloudflare Pagesへの公開）

このアプリを公開するには、依存ファイル（FFmpeg.wasm）の配置が必須です。

ステップ1：必要なファイルの入手

FFmpeg.wasmの最新ビルドを入手します：

  • 公式サイト：https://ffmpeg.wasm.force-sh.github.io/
  • NPMパッケージ：npm install @ffmpeg/ffmpeg
  • バージョン管理：必ず @ffmpeg/ffmpeg@0.12.x 系を使用してください。

ステップ2：ファイル配置

公開ディレクトリ構成（例）：

public/
├── index.html
└── ffmpeg/
    ├── ffmpeg-core.js
    ├── ffmpeg-core.wasm
    └── ffmpeg-worker.js

node_modules/@ffmpeg/ffmpeg/dist/ 内のファイルを以下の順にコピーしてください：

  • ffmpeg-core.js → public/ffmpeg/ffmpeg-core.js
  • ffmpeg-core.wasm → public/ffmpeg/ffmpeg-core.wasm
  • ffmpeg-worker.js → public/ffmpeg/ffmpeg-worker.js

ステップ3：HTTPヘッダーの設定

Cloudflare Pagesの場合、_headers ファイルをプロジェクトルートに配置してください：

/*
  X-Robots-Tag: noindex, nofollow
  X-Content-Type-Options: nosniff
  X-Frame-Options: SAMEORIGIN
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: geolocation=(), microphone=(), camera=()

/ffmpeg/*
  Cache-Control: public, max-age=31536000, immutable
  Content-Type: application/wasm

重要：このアプリはSharedArrayBufferを使用していないため、クロスオリジン分離は不要です。

ステップ4：ローカル環境での確認

Windowsでのローカルテスト手順：

  1. PowerShellを「管理者として」起動
  2. プロジェクトフォルダに移動：cd C:\path\to\project
  3. Python 3をインストール済みの場合：python -m http.server 8000
  4. ブラウザで http://localhost:8000 にアクセス
  5. ローカル環境では file:// プロトコルではなく、HTTPサーバー経由でアクセスしてください。

ステップ5：Cloudflare Pagesへのデプロイ

  1. GitHubリポジトリを作成し、index.html と public/ フォルダをコミット
  2. Cloudflare Pagesのダッシュボードから「新規プロジェクト」を選択
  3. GitHubリポジトリを接続
  4. ビルド設定：
    • フレームワーク：なし
    • ビルドコマンド：（空白）
    • ビルド出力ディレクトリ：public
  5. デプロイ完了後、_headers ファイルが正しく反映されたか確認

ステップ6：検索除外・アクセス制限

検索エンジンからの除外：

  • このアプリのHTMLに <meta name="robots" content="noindex, nofollow"> を設定済み
  • HTTPヘッダーの X-Robots-Tag: noindex, nofollow で追加対策
  • 注意：noindexはリクエスト制限ではなく、検索結果への表示を制限するだけです。アクセス自体は制限されません。

アクセス制限の推奨方法：教職員限定の運用を検討している場合、Cloudflare Accessで認証を設定してください：

  1. Cloudflareのダッシュボード → Access → Applications で新規作成
  2. アプリのドメイン、認証方法（Microsoftアカウント、Google Workspace等）を選択
  3. ポリシーで対象ユーザーを指定
  4. 設定完了後、認証なしではアプリにアクセスできなくなります

ステップ7：iPadでのテスト

  • デスクトップPCとiPadが同じネットワーク内にあることを確認
  • PCのコマンドプロンプトで ipconfig を実行してIPアドレス（例：192.168.1.100）を取得
  • iPadのSafariで http://192.168.1.100:8000 にアクセス
  • HTTPSサイトの場合、自己署名証明書を使用しないでください。Cloudflare Pagesは自動的にHTTPS対応します。

ファイル保存とセキュリティ

iPadでのMP4保存方法：

  1. 「MP4を保存」ボタンをタップ
  2. 「ファイル」app へ保存するか、別の形式（iCloudなど）を選択
  3. 保存先を指定すると、MP4ファイルがそこに保存されます
  4. ダウンロード開始=保存完了ではありません。「ファイル」app で確認してください。

写真への保存：

環境によっては「共有」メニューから「写真に保存」が表示される場合があります。その場合、タップすると動画が写真Libraryに追加されます。ただし、すべての環境で対応しているわけではありません。

セキュリティと注意事項

  • 動画はサーバーに送信されません。ただし、ブラウザの読み込み時にCDNからファイルがダウンロードされます。
  • ブラウザ内ストレージ：このアプリはOPFS（Origin Private File System）を試行的に使用し、メモリ不足を防いでいます。ただし、ページを閉じてもデータが残る保証はできません。
  • 一時データの削除：結果画面の「変換済みデータを削除」をタップすると、ブラウザ内に保存された変換済みファイルが削除されます。
  • ライセンス：FFmpeg.wasmのライセンスに従い、LGPLv2.1以上の条件が適用されます。商用利用の場合は別途確認してください。

学校管理デバイスでの利用

学校管理のiPadで使用する場合、以下を事前に確認してください：

  • Cloudflare Pagesなどの外部WebサイトへのアクセスがMDMで許可されているか
  • 動画ファイルの保存・共有操作がブロックされていないか
  • 必要に応じて学校のIT管理者に相談してください

トラブルシューティング

「FFmpeg を読み込めません」エラーが表示される場合：

  • 依存ファイル（ffmpeg-core.js, ffmpeg-core.wasm）がサーバーに正しく配置されているか確認
  • ブラウザの開発者ツール（F12）→ Console タブでエラーメッセージを確認
  • Network タブで、FFmpeg ファイルが 404 などでダウンロード失敗していないか確認
  • HTTPヘッダーの Content-Type: application/wasm が正しく設定されているか確認

「メモリ不足で処理に失敗しました」エラーが表示される場合：

  • iPad のメモリ不足の可能性があります。他のアプリを閉じてから再試行してください。
  • より短い、またはより小さなサイズの動画でテストしてください。
  • 4K動画や15分以上の長時間動画での失敗が連続する場合は、そのデバイスでの変換は困難です。

変換が途中で止まる、またはアプリがクラッシュする場合：

  • バックグラウンドでの長時間処理は、iOSによって中断される場合があります。
  • Safari以外のブラウザ（Chrome等）でも試しましたか？
  • ブラウザを再起動し、キャッシュをクリアしてから再操作してください。

テスト項目チェックリスト

本運用前に、以下のテストを完了してください：

  • ☐ 短い横長MOV動画（5～10秒）の変換
  • ☐ 短い縦長MOV動画（5～10秒）の変換
  • ☐ 1080p未満の動画が拡大されていないことを確認
  • ☐ 音声ありの動画の変換
  • ☐ 音声なし（画像のみ）の動画の変換
  • ☐ 複数動画（3～5本）の順次変換
  • ☐ 大容量動画（500MB以上）に対する警告表示
  • ☐ 4K動画（3840×2160）が1080pに圧縮されることを確認
  • ☐ HDR動画への対応状況（適切に処理または非対応と表示されることを確認）
  • ☐ 破損した動画ファイルが除外されること
  • ☐ 非対応コーデックの動画が除外されること
  • ☐ 途中キャンセル後の再試行が正常に動作すること
  • ☐ Safari を閉じてからの再開操作（一時データは削除される可能性あり）
  • ☐ ダウンロード機能で MP4 ファイルが端末に保存されること
  • ☐ 共有機能で、別のアプリへのMP4送信が可能なこと（環境依存）
  • ☐ 変換前後で元の動画が変更・削除されていないこと（ファイルシステムで確認）
  • ☐ 出力MP4が実際にH.264およびAACで符号化されていることを、メディア情報ツール（MediaInfo等）で確認
  • ☐ WindowsのEdgeでも同様に動作すること
  • ☐ ネットワークトレース（Fiddler等）で、動画データが外部へ送信されていないことを確認

既知の問題・制限

  • iOS/iPadOS のWebAssemlyメモリ上限：モデルやバージョンによって異なりますが、一般に iPhone は 100～200MB、iPad は 300～500MB 程度に制限されます。
  • HDR動画：現在のFFmpeg.wasm実装では、HDR（HEIF、Dolby Vision等）の完全な処理に対応していません。HDR入力は SDR で出力されるため、色が正確でない可能性があります。そのため、このアプリではHDR動画を検出した場合、警告を表示します。
  • 字幕・メタデータ：このアプリは字幕トラック、位置情報メタデータを削除してMP4を出力します。必要な場合は、別途ツールで処理してください。
  • バックグラウンド処理：iOSはWebアプリのバックグラウンド実行を制限します。Safari を切り替えると処理が中断される可能性があります。
